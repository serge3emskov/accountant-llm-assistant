# accountant-LLM-assistant

Долгосрочная память (LTM) **AI-ассистента бухгалтера** на синтетических данных. Ассистент общается с бухгалтером и помнит, что тот рассказывал о компании: режим налогообложения, плательщик ли НДС, контрагенты, договоры, первичные документы, отчётность, учётные практики и нерешённые расхождения.

Архитектура построена на принципе:

> **LLM понимает смысл, состоянием памяти управляет код.** Модель классифицирует запрос и извлекает из диалога структурированные события. Всё остальное детерминировано: валидация, нормализация названий и ИНН, ID, время, тип изменения, итоговый статус факта, выборка контекста и проверка операций по справочнику.

⚠️ **Это демо-версия.** Все контрагенты, документы и выписки — синтетические. Ставки и лимиты в справочнике приведены как справочные и требуют сверки с действующей редакцией НК РФ на дату операции. Ассистент не заменяет главного бухгалтера и не даёт юридических гарантий.

## Принцип

```
write-path (фон)
  диалог ─► [LLM] разделы ─► [LLM] extractor ─► Pydantic-валидация ─► нормализация ─► state machine ─► SQLite
                                                   невалидное → rejections     название → ИНН/ключ     facts + events

read-path (синхронно)
  запрос ─► [LLM] тип запроса ─► набор разделов ─► фильтр статусов и сроков ─► контекст с пометкой источника
                                                                              + список «уточнить у бухгалтера»
ответ
  профиль из памяти + операции из вопроса ─► правила по справочнику ─► блок «ПРОВЕРКА» в контексте
  ─► [LLM] ответ ─► операции из ответа ─► те же правила ─► неучтённое предупреждение дописывает код
```

## Разделы памяти

| Раздел | Что хранит | Тип | Особенности |
|---|---|---|---|
| `company_profile` | режим, НДС, объект УСН, численность, выручка, освобождение от НДС | атрибуты | выручка/численность устаревают → «уточнить» |
| `counterparties` | контрагенты (ключ — нормализованное название, ИНН в атрибутах) | сущности | «нет» ≠ «нет данных»; отрицание → `terminated` |
| `contracts` | договоры: сумма, предмет, условия оплаты | сущности | сумма извлекается из текста («150 тысяч» → 150000) |
| `documents` | первичка и счета-фактуры: ожидаем/получен/проведён/отсутствует | сущности | отрицание → `missing` |
| `obligations` | отчётность и платежи: предстоит/сдано/просрочено | сущности | «отчётности нет» на уровне раздела |
| `issues` | проблемы и расхождения | сущности | срок актуальности 30 дней → «забывание» |
| `practices` | наличные расчёты, ККТ, ЭДО | атрибуты | слово-маркер в цитате обязателен |

Субъекты: `self` (своя компания), `дочка`, `ип директора`, `филиал` — факты изолированы по субъекту.

## LLM-шаги

Модель — [Qwen3-4B-Instruct-2507](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507), 4-bit NF4 в Colab T4, жадное декодирование.

| Шаг | Что делает модель | Что делает код |
|---|---|---|
| Классификатор разделов | какие разделы затронуты в диалоге | отбрасывает неизвестные разделы; при сбое — extractor по всем; **страховка**: контрагент из реестра или «контрагентов нет» добавляет раздел |
| Extractor | события по **одному** разделу | повтор при битом JSON и невалидных событиях, отсечение фактов чужого раздела, проверка ИНН по контрольным цифрам, цитата `evidence` должна найтись в диалоге |
| Классификатор запроса | тип запроса и о какой компании | отбрасывает неизвестные типы; при сбое — правила |
| Ответ | ответ бухгалтеру | контекст с пометкой источника, блок СПРАВОЧНИК, блок ПРОВЕРКА, список «уточнить» |

Бэкенды с одним интерфейсом: `QwenTransformersLLM` (Colab), `OpenAICompatLLM` (vLLM, Ollama, LM Studio), `CachedLLM` (кэш на диск), `ScriptedLLM` (тесты).

## Справочник и проверка соответствия

`AccountingCatalog` хранит:
* **операции** (~30 типов: НДС к вычету, наличные расчёты, расходы УСН, зарплата, дивиденды, подотчёт, ГПХ, импорт…);
* **план счетов** (28 счетов с разговорными алиасами: «расчётный счёт» → 51, «касса» → 50);
* **отчётность** (декларация НДС/УСН, 6-НДФЛ, РСВ, ЕФС-1, уведомление ЕНП…);
* **синтетический реестр контрагентов** (60 организаций и ИП с валидными ИНН и риск-флагами: адрес массовой регистрации, дисквалифицированный директор, молодая компания).

`ComplianceChecker` проверяет операции по профилю компании **в коде**, до и после ответа модели: 25 правил в `compliance_data/rules.json` + встроенные проверки контрагентов и первички. Примеры:

| Правило | Суть |
|---|---|
| `r-cash-limit` | наличные расчёты между юрлицами/ИП свыше 100 000 ₽ по одному договору — не допускается (Указание Банка России № 5348-У) |
| `r-usn-income-exp` | при объекте УСН «доходы» расходы не уменьшают налог |
| `r-psn-vat` | на ПСН/НПД/АУСН нет НДС к вычету |
| `r-div-usn-exp` | дивиденды не учитываются в расходах УСН |
| `r-usn-employees` / `r-usn-revenue` | лимиты УСН: 130 человек, 450 млн ₽ |
| `cp_disqualified` / `cp_mass_address` / `cp_young` | должная осмотрительность по контрагенту (ст. 54.1 НК РФ) |
| `no_primary_docs` | расход без первичных документов не принимается |

Если модель не назвала причину предупреждения в ответе, код дописывает его сам.

## Синтетические данные

Генератор `scripts/build_synthetic_data.py` (детерминированный, seed=42) создаёт:
* `data/synthetic/counterparties.json` — 60 контрагентов, ИНН с корректными контрольными цифрами;
* `data/synthetic/documents.jsonl` — 120 первичных документов и счетов-фактур;
* `data/synthetic/bank_statement.csv` — 84 платёжных поручения (выписка банка).

Выписка подключается как **документированный источник** (`DocumentRecord`): если документы расходятся со словами бухгалтера, ассистент уточняет, а не выбирает версию сам.

Живой диалог с локальной моделью (Ollama / vLLM / LM Studio):

```python
from acctltm import AccountantAssistant
from acctltm.llm import OpenAICompatLLM

llm = OpenAICompatLLM("http://localhost:11434/v1", "qwen3:4b")
assistant = AccountantAssistant(llm)
session = assistant.session("company-1")
print(session.say("Мы на УСН доходы, работаем с Ромашкой как поставщик."))
session.close()  # write-path: память сохраняется
print(session.say("Можно оплатить Ромашке наличными 150 тысяч и принять расходы?"))
```

## Оценка

Детерминированная оценка (без GPU) прогоняет **эталонные ответы extractor-а** через весь write-path и read-path и проверяет, что код и разметка согласованы:

* `data/dev_dialogs.jsonl` — 10 диалогов, `data/dev_queries.jsonl` — 12 запросов;
* `data/golden/scenarios.jsonl` — 16 сценариев (включая многосессионные и пробы контекста), `data/golden/queries.jsonl` — 16 запросов;
* `data/compliance/cases.jsonl` — 12 кейсов проверки соответствия.

Тесты требуют 100% совпадения итогового состояния памяти с эталоном (F1 = 1.0) и прохождения всех кейсов комплаенса. Это проверка **кода и разметки**, а не модели: LLM-метрики (F1 классификатора, extractor-а, памяти) измеряются отдельно при наличии GPU — см. `notebooks/02_llm_pipeline.ipynb`.

Базовый классификатор запросов на правилах даёт ≈0.75–0.83 точного совпадения типов на dev/golden — нижняя планка для сравнения с LLM.

## Структура

```
src/acctltm/
  sections.py        разделы памяти и их политики
  schemas.py         Pydantic-контракт событий extractor-а
  lexicon.py         нормализация: clean_name, суммы, ИНН, нечёткий поиск
  reference_data.py  операции, план счетов, отчётность, контрагенты, ставки
  catalog.py         AccountingCatalog
  normalize.py       Normalizer (название → ключ факта)
  memory.py          state machine: событие → изменение памяти
  store.py           SQLite: facts + events + section_states + rejections
  compliance.py      проверка ограничений по справочнику
  compliance_data/   classes.json, rules.json
  retrieval.py       read-path: тип запроса → контекст
  prompts.py         промпты четырёх LLM-шагов
  query_rules.py     baseline-классификатор запроса
  followup.py        уточняющие вопросы, дописанные кодом
  pipeline.py        write-path / read-path / AccountantAssistant / ChatSession
  llm.py             бэкенды LLM
  devcheck.py        прогон dev-набора
  evaluation.py      оценка по слоям, метрики P/R/F1
  synthetic.py       загрузчики синтетических данных
scripts/             генератор синтетики, демо
notebooks/           01_core_demo, 02_llm_pipeline, 03_compliance
tests/               100 тестов (pytest, без GPU)
data/                dev/golden наборы, кейсы комплаенса, синтетика
```
